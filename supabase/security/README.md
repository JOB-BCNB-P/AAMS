# นโยบายสิทธิ์และตรรกะฝั่งฐานข้อมูลของ AAMS

โฟลเดอร์นี้คือ **สำเนา ณ เวลาหนึ่ง** ของชั้นความปลอดภัยที่อยู่ในฐานข้อมูล Supabase
เก็บไว้ในโปรเจกต์เพื่อสองเรื่อง

1. **ตรวจสอบได้** — ผู้ตรวจประเมิน (AUN-QA / EdPEx / ผู้ตรวจสอบภายใน) อ่านได้ว่าใครเห็นข้อมูลอะไรบ้าง
   โดยไม่ต้องเข้าหน้าจัดการฐานข้อมูล และเห็นประวัติการเปลี่ยนแปลงผ่าน git
2. **กู้คืนได้** — ถ้าต้องย้ายโปรเจกต์หรือสร้างใหม่ ไฟล์เหล่านี้ทำให้ตั้งสิทธิ์กลับมาเหมือนเดิมได้

> ⚠️ ไฟล์เหล่านี้ **ไม่ใช่** ตัวจริง ตัวจริงอยู่ในฐานข้อมูล
> แก้ไฟล์ที่นี่แล้วสิทธิ์ในระบบไม่เปลี่ยนตาม ต้องนำไปรันที่ SQL Editor ของ Supabase เท่านั้น

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | เนื้อหา |
|---|---|
| `01_helpers.sql` | ฟังก์ชันตัวช่วยในสกีมา `ems` — ตัวตัดสินว่า "คนที่ล็อกอินอยู่คือใคร มีบทบาทอะไร" |
| `02_policies.sql` | นโยบาย Row Level Security ของทุกตารางในสกีมา `public` |
| `03_rpc.sql` | ฟังก์ชัน `ems_*` ที่หน้าเว็บเรียกใช้ (SECURITY DEFINER) |
| `90_export.sql` | สคริปต์ดึงสำเนาชุดใหม่ออกมา เมื่อมีการแก้สิทธิ์ในฐานข้อมูล |

## วิธีอัปเดตสำเนาให้ตรงกับของจริง

1. เปิด Supabase → SQL Editor
2. รัน `90_export.sql`
3. คัดลอกผลลัพธ์ของแต่ละส่วนมาวางทับไฟล์ `01_` `02_` `03_`
4. commit ขึ้น git — diff จะบอกเองว่าสิทธิ์อะไรเปลี่ยนไปบ้าง

ควรทำทุกครั้งที่มีการเพิ่มตารางใหม่หรือแก้นโยบายสิทธิ์

## หลักที่ยึดไว้

- **ทุกตารางเปิด RLS** ไม่มีข้อยกเว้น ตรวจได้ด้วยคำสั่งท้ายไฟล์ `90_export.sql`
- **สิทธิ์ตัดสินที่ฐานข้อมูล ไม่ใช่ที่หน้าจอ** หน้าเว็บซ่อนปุ่มเพื่อความสะดวกของผู้ใช้
  แต่ถึงแก้หน้าเว็บก็อ่านหรือเขียนข้อมูลที่ไม่มีสิทธิ์ไม่ได้
- **บทบาทอ่านจาก `app_user` ของบัญชีที่ล็อกอิน** ผ่าน `ems.my_roles()` ไม่ใช่จากค่าที่หน้าเว็บส่งมา
- ตาราง `drive_link` เปิด RLS ไว้แต่**ไม่มีนโยบายใดเลย โดยตั้งใจ** — เก็บ refresh token ของ Google
  จึงต้องอ่านได้เฉพาะ Edge Function ที่ใช้ service role เท่านั้น ห้ามเพิ่มนโยบายให้ตารางนี้

## กลุ่มบทบาทที่ใช้บ่อย

| ฟังก์ชัน | ครอบคลุมบทบาท |
|---|---|
| `ems.is_full()` | admin, academic, registrar |
| `ems.is_educator()` | is_full + deptHead, teacher, classTeacher |
| `ems.is_staff()` | is_educator + executive |
| `ems.sees_all_students()` | admin, academic, registrar, executive, otherStaff |

## บันทึกการเปลี่ยนแปลงสำคัญ

- **29 ก.ย. 2569** ยกเลิกการเข้าระบบด้วยเลขบัตรประชาชนโดยสิ้นเชิง
  - Edge Function `student-login` เปลี่ยนเป็นตัวเปล่าที่ตอบ 410 และตั้ง `verify_jwt = true`
  - รหัสผ่านของบัญชีภายใน `<รหัสนักศึกษา>@student.bcnb.local` ทั้ง 808 บัญชี
    เดิมถูกตั้งเป็น "เลขบัตรประชาชน" ของเจ้าตัว จึงยิงเข้า `/auth/v1/token` ตรง ๆ ได้
    แก้แล้วโดยเปลี่ยนเป็นค่าสุ่มยาวที่ไม่มีใครรู้
  - ตัดสาขา `student.bcnb.local` ออกจาก `ems.link_auth_user()`
  - เลขบัตรยังเก็บไว้เป็นประวัติในตาราง `student_private` (อ่านได้เฉพาะ `ems.is_full()`)
    และเปิดให้ผู้ดูแลระบบดูผ่าน `ems_student_nid()` ซึ่งปิดบังสามตัวท้ายมาจากฐานข้อมูลแล้ว
  - ถอนสิทธิ์ `anon` ออกจากฟังก์ชัน SECURITY DEFINER ที่ถูกให้สิทธิ์อัตโนมัติตอนสร้าง
  - ตั้ง `search_path` ให้ฟังก์ชันที่ยังขาด กันการสลับ search_path ไปเรียกตารางปลอม

## เรื่องที่ต้องไปกดเองในหน้าจัดการ Supabase (สั่งด้วย SQL ไม่ได้)

- **Leaked password protection** — Authentication → Policies → เปิด
  ป้องกันการตั้งรหัสผ่านที่เคยหลุดจากที่อื่นมาแล้ว (เทียบกับฐานข้อมูล HaveIBeenPwned)
  ตอนนี้ยังปิดอยู่ · มีผลเฉพาะบุคลากรที่ยังใช้รหัสผ่าน เพราะนักศึกษาเข้าด้วย Google หมดแล้ว
- **บัญชีภายในที่เหลืออยู่** — ยังมี 808 บัญชีอีเมล `<รหัสนักศึกษา>@student.bcnb.local`
  รหัสผ่านถูกเปลี่ยนเป็นค่าสุ่มแล้ว จึงเข้าระบบไม่ได้อีก
  แต่ถ้าต้องการเก็บกวาดให้หมด ลบได้เมื่อนักศึกษาย้ายไปใช้บัญชี Google ครบทุกคนแล้ว
  (ตรวจได้ด้วยคำสั่งท้าย `90_export.sql`)

## รายการตรวจก่อนขึ้นระบบทุกครั้งที่แก้สิทธิ์

1. รัน `90_export.sql` ส่วนที่ 0 — ผลลัพธ์ทั้งสี่ข้อต้องว่าง ยกเว้น `drive_link` ในข้อ 0.2
2. คัดลอกส่วนที่ 4 ไปวางทับ `tests/rls_live.txt`
3. รัน `node tests/test_rls_snapshot.js` — ต้องผ่านทุกข้อ
4. commit ทั้งไฟล์สำเนาและ `rls_live.txt` ไปพร้อมกัน
