# ข้อมูลจำลองสำหรับทดสอบ

| ไฟล์ | หน้าที่ |
|---|---|
| `counsel_demo.sql` | ใส่ข้อมูลจำลองของระบบให้คำปรึกษานักศึกษา |
| `counsel_demo_teardown.sql` | ลบข้อมูลจำลองออกให้หมด |

## หลักที่ยึด

* **ไม่มีข้อมูลบุคคลจริง** ชื่อเป็น "ทดสอบ หนึ่ง … ทดสอบ แปด" ไม่มีเลขบัตรประชาชน ไม่มีเบอร์โทร ไม่มีที่อยู่
* **แยกออกจากข้อมูลจริงได้ชัด** รหัสนักศึกษาจำลองขึ้นต้น `99` ซึ่งไม่ตรงรูปแบบรหัสจริง และรายการให้คำปรึกษาขึ้นต้น `DEMO-CS`
* ทุกแถวติด `extra -> demo = "counsel"` ไว้อีกชั้น เผื่อต้องค้นย้อนหลัง
* ลบได้ปลอดภัย ไฟล์ teardown ผูกเงื่อนไขกับรหัสจำลองเท่านั้น

## สิ่งที่ข้อมูลชุดนี้ให้ทดสอบได้

| เรื่อง | ทดสอบด้วย |
|---|---|
| คำนวณเวลา | `DEMO-CS1` 90 นาที ต้องขึ้น 1.50 ชม. · `DEMO-CS3` 45 นาที ต้องขึ้น 0.75 ชม. |
| การส่งต่อ | `DEMO-CS2` สถานะส่งต่อ พร้อมหน่วยงานและเหตุผล |
| คำปรึกษาแบบกลุ่ม | `DEMO-CS3` มีนักศึกษา 3 คน คนละชั้นปี ผลร่วมอยู่ในช่องผลการให้คำปรึกษา ประเด็นเฉพาะรายอยู่ในบันทึกส่วนตัวของแต่ละคน |
| การจำกัดสิทธิ์ | เข้าระบบเป็น **อ.ทดสอบ ที่ปรึกษา** ต้องเห็น CS1–CS3 แต่ต้องไม่เห็น CS4 · เข้าเป็นผู้ดูแลต้องเห็นทั้งสี่ · เข้าเป็นงานกิจการนักศึกษาต้องเห็นเฉพาะ CS2 |
| เลือกนักศึกษารายชั้นปี | มีนักศึกษาชั้นปี 1–4 ชั้นปีละ 2 คน |
| สบช.โมเดล | `9900000101` มี 2 รายการ BMI ต้องได้ 25.34 และ 33.09 |
| การเจ็บป่วยแยกจากการลา | `9900000101` มีลาป่วย 1 + ลาพบแพทย์ 1 + ลากิจ 1 → คอลัมน์การเจ็บป่วยต้องนับ 2 คอลัมน์การลาต้องนับ 3 |
| คอลัมน์ที่ยังไม่มีข้อมูล | `9900000102` ไม่มีทั้งสบช.โมเดล ความประพฤติ และใบลา ต้องขึ้นว่า "ไม่มีข้อมูล" ไม่ใช่หน้าว่าง |

## ข้อควรระวัง

ถ้าจะทดสอบว่าอาจารย์เห็นเฉพาะนักศึกษาในที่ปรึกษาของตน ต้องมีบัญชีอาจารย์ชื่อ
**อ.ทดสอบ ที่ปรึกษา** และ **อ.ทดสอบ อีกท่าน** ในตาราง `app_user` ด้วย
เพราะการกรองอิงชื่อในช่อง `advisor` ของทะเบียนนักศึกษา
หรือจะแก้ชื่อที่ปรึกษาในไฟล์ให้ตรงกับบัญชีอาจารย์ที่มีอยู่จริงสองท่านก็ได้
